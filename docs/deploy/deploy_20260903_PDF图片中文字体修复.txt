识图 PDF/图片中文字体与两栏布局修复

问题原因：
1. CentOS Stream 9 安装的 Noto Sans CJK 是 CFF-in-TTC 格式。
2. PDFBox 2.x 对该字体开启子集时会报“OTF fonts do not have a glyf table”，关闭子集时又不支持完整嵌入 TTC。
3. 字体未实际嵌入后，PDF 回退到不包含中文的字体，中文最终显示为 ####。
4. OpenHTMLToPDF 不完整支持 CSS Grid、CSS 变量和部分 calc 表达式，所以 PDF 两栏布局会退化。

本次修复：
1. 部署脚本按固定 Git 提交下载开源文泉驿微米黑 TrueType 字体，并使用 SHA-256 校验后安装到项目专用字体目录。
2. PDF 渲染改用可子集化的 TrueType 字体，不再选用不兼容的 CFF-in-TTC 字体。
3. 识图 PDF 生成后会再检查字体是否真正嵌入、中文是否可提取；失败时返回明确错误，不再输出伪成功的乱码文件。
4. 识图模板改为 OpenHTMLToPDF 兼容的 48% inline-block 两栏，移除影响 PDF 布局的 CSS Grid、CSS 变量和关键 calc 宽度。

发布前验证：
1. 生产机最小复现确认：Noto CFF-in-TTC 子集模式抛错，完整嵌入模式生成的文本为 #### ABC。
2. 新 TrueType 字体最小渲染成功，PDF 可提取“中文测试 ABC”。
3. 多卡片 A4 预览实际渲染为 2 页，中文、两栏、分页、标签和边框均无缺字、裁切或重叠。
4. Java 17 执行 `mvn test`：56 个测试通过，1 个对象存储集成测试跳过。
5. 前端执行 `npm run build`：通过。
