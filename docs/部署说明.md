# 生产环境部署说明

运行环境要求 Java 17、Maven 3.6+、Node.js 20.19+、MySQL 8 和 Redis 6+。

## 固定流程

1. 在本地完成代码修改和数据库迁移脚本。
2. 本地执行后端测试与前端构建。
3. 按 Git 提交规范提交，并推送到远端 `main`。
4. 登录服务器后执行 `/home/ai_techskill_book/scripts/deploy-server.sh`。
5. 检查后端健康状态、首页、核心接口、Redis 和服务日志。
6. 在 `docs/deploy` 新增本次部署日志，并随下一次提交归档；重要部署应在本次发布前写好日志。

禁止直接修改 `/home/ai_techskill_book` 中的业务源码。服务器只允许通过 Git 快进拉取已经验证的提交。

## 服务器连接和凭据

服务器连接是允许的常规运维操作，但连接信息和认证信息必须分离管理：SSH 主机、端口和用户名保存在本机未跟踪的连接配置中；密码、私钥口令和 Git Token 只保存在操作系统钥匙串、服务器受限文件或批准的密钥管理系统。不得将真实值写入本说明、部署日志、命令行参数、AI 提示词或 Git 提交。

远程检查优先使用服务健康状态、版本、迁移版本和脱敏后的配置键名。不得读取或输出完整环境文件；需要验证配置时，仅确认所需变量存在、权限正确且服务能够连接。生产变更仍遵循本说明的固定流程，并在执行前获得明确授权。

本机 SSH 工具可能被多个项目共用，默认配置不保证指向本项目生产机。连接后必须先只读核对主机、`/home/ai_techskill_book`、当前分支和 `ai-techskill-book.service`；任一项不匹配时立即停止，不得在其他服务器执行本项目部署。

确认只读校验输出包含 `main` 和 `ai-techskill-book.service` 后，再执行：

```bash

OPS_KEYCHAIN_SERVICE=com.codex.ops-terminal.38.22.90.174 \
```

`scripts/deploy-server.sh` 自身也会进行生产防误部署校验：当前主机必须包含 `38.22.90.174`，项目目录必须是 `/home/ai_techskill_book`，分支必须是 `main`，`origin` 必须指向本项目仓库，且必须存在 `ai-techskill-book.service` 和对应 HTTPS 证书；任一条件不满足会在部署前退出。

未显式设置 `AI_MODEL` 时默认使用 `gpt-5.6-terra`；识图任务建议保持该模型或在本地验证后再切换。

头像等遗留文件仍使用私有对象存储；Markdown 正文的新来源是 MySQL。首次迁移历史文章时，显式设置 `DOCUMENT_MIGRATE_OBJECT_STORAGE_ON_STARTUP=true`，确认迁移和索引任务完成后立即关闭。正常文档编辑不再上传或删除对象存储文件。

文档索引由 Kafka 异步投递到主平台，再由主平台分块写入 Elasticsearch。后端只通过环境变量读取 Kafka、ES 和 OpenAI 兼容 API 配置；真实密码、Token 和 API 密钥不得写入仓库、日志或提示词。`INDEX_ENABLED=false` 时不建立索引消费者连接。

真实值只能保存在服务器环境文件或本地密钥管理工具中，不得提交到 Git、部署日志或 AI 提示词。仓库中的 `deploy/backend.env.example` 仅用于列出所需键和非敏感默认值。

生产环境必须使用 `SESSION_SECURE_COOKIE=true`，并通过 HTTPS 提供登录功能。本地开发使用 HTTP 时才允许设置为 `false`。

Flyway 迁移失败时不得直接反复重启服务。先停止应用、确认失败版本和业务 SQL 已回滚，再只删除对应的 `success=0` 历史记录，最后重新启动让修复后的迁移重跑；不得删除成功迁移记录或业务表数据。

生产环境启用头像上传时必须设置 `STORAGE_ENABLED=true` 和 `STORAGE_ENVIRONMENT=prod`。对象存储桶保持私有，真实凭据仅写入 `/etc/ai-techskill-book/backend.env`，更新时文件权限保持为仅 root 可写、服务用户可读。

## HTTPS 证书

当前公网 IP 证书由 Certbot 管理，证书文件位于 `/etc/letsencrypt/live/38.22.90.174`。IP 证书有效期较短，`certbot-renew-ai-techskill-book.timer` 每天检查三次续期，续期成功后自动重载 Nginx。每次部署必须确认定时器为 `active`，并使用 HTTPS 验证首页和接口。

## 回滚

部署脚本会把上一版产物和 Nginx 配置保存到 `/opt/ai-techskill-book/backups/<部署时间>`。应用发布失败时，恢复其中的 `app.jar`、`frontend.tar.gz` 和 Nginx 配置，然后重启后端与 Nginx。数据库回滚必须根据对应迁移脚本单独评估，不允许直接删除生产数据。
