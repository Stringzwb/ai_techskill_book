# Elastic Stack 运维说明

## 服务管理

```bash
cd /opt/elasticsearch

# 查看状态
docker compose ps
docker stats --no-stream elasticsearch kibana

# 启动或对齐当前配置
docker compose up -d

# 分别重启
docker compose restart elasticsearch
docker compose restart kibana

# 查看日志
docker compose logs --tail=100 elasticsearch
docker compose logs --tail=100 kibana
```

## 健康检查

```bash
set -a
source /opt/elasticsearch/.env
set +a

curl -u "elastic:${ELASTIC_PASSWORD}" \
  'http://127.0.0.1:9200/_cluster/health?pretty'
curl -fsS -o /dev/null -w '%{http_code}\n' \
  'http://127.0.0.1:5601/login'
docker inspect --format '{{.State.Status}} {{.State.Health.Status}}' \
  elasticsearch kibana
```

预期 Elasticsearch 集群状态为 `green`，Kibana 登录页返回 `200`，两个容器均为 `running healthy`。

## 配置同步

服务器当前配置的归档副本为 `es/compose.yaml`。配置调整应先更新归档文件并校验，再备份服务器现有文件，最后使用下列命令对齐容器：

```bash
cd /opt/elasticsearch
docker compose config --quiet
docker compose up -d
```

真实 `.env` 不得提交 Git。恢复到新服务器时，从 `.env.example` 创建新的强密码和加密密钥，不应默认复用旧凭据。

## 端口规则

所有 Docker 中间件均使用宿主机与容器相同的端口号。当前发布 `9200:9200` 和 `5601:5601`。新增公网端口时必须同时配置身份认证并登记用途。

## 备份边界

`es/` 保存可移植配置、历史 Compose 备份和 `test1` 测试数据。`/srv/elasticsearch/data` 和 `/srv/kibana/data` 是运行时二进制数据，不可直接复制进 Git；生产索引应使用 Elasticsearch Snapshot 仓库备份。
